# Gemini Project Overview: Mac Disk Usage Logger

## 1. Project Purpose

This project provides a set of tools to automatically log disk I/O on macOS. The goal is to monitor disk usage over time to quantify I/O and help prevent excessive wear on SSDs.

It uses `launchd` for scheduling, `iostat` for collecting data, and a suite of Python scripts for parsing, storing, and managing the data. Data is stored in a versioned `DuckLake` database, with an option to sync to `MotherDuck` for cloud storage.

## 2. Key Technologies

- **Python**: Core language for all data processing and management scripts.
- **uv**: Used for Python environment and dependency management.
- **just**: A command runner for executing common project tasks defined in the `.justfile`.
- **DuckDB & DuckLake**: The primary data store. DuckDB is the query engine, and DuckLake provides a versioning layer on top of Parquet files, allowing for historical data snapshots.
- **Pandas**: Used for data manipulation when parsing the log files.
- **Typer**: Used to create the command-line interfaces for the Python scripts.
- **launchd**: The native macOS scheduler used to run the logging script automatically.
- **gnuplot**: Optional dependency for plotting data directly in the terminal.
- **MotherDuck**: Optional cloud backend for storing data.

## 3. Project Structure

- **`.justfile`**: Contains recipes for common tasks like loading the schedule, parsing data, and managing the database. This is the preferred way to interact with the project.
- **`pyproject.toml` / `uv.lock`**: Defines Python dependencies for `uv`.
- **`.env`**: (User-created) Stores configuration like paths and API tokens.

- **`log_disk_usage.sh`**: The core shell script that runs `iostat` and appends the output to a log file. It is scheduled by `launchd`.
- **`templates/com.diskusagelog.plist`**: The template for the `launchd` job configuration.

- **`parse_disk_usage.py`**: A CLI tool to parse the raw log file (`logged_disk_usage.txt`), calculate disk usage deltas, and save the structured data to DuckLake and/or MotherDuck.
- **`manage_ducklake.py`**: A CLI tool for managing the DuckLake database, including viewing data, listing snapshots, pruning old history, and merging files.
- **`load_schedule.py`**: A script that populates the `launchd` plist template and loads it, setting up the scheduled logging.

- **`data/`**: The default directory for data storage.
  - `logged_disk_usage.txt`: The raw, append-only log file generated by the `log_disk_usage.sh` script.
  - `disk_usage.ducklake`: The DuckLake metadata file for the versioned database.
  - `disk_usage.ducklake.files/`: Directory containing the actual data in Parquet files.

## 4. Common Workflows & Commands

The project is best interacted with via the `just` commands.

### Setup
1.  **Install dependencies**: `uv sync`
2.  **Configure environment**: Create a `.env` file with necessary paths and tokens (see `README.md`).
3.  **Load schedule**: `just load` (or `uv run python load_schedule.py`) to start the automated logging.

### Data Processing
-   Data is logged automatically in the background.
-   To process the logs and save them to the database, run:
    -   `just parse`: Parses logs and stores them in DuckLake.
    -   `just save`: Parses logs and saves to both DuckLake and MotherDuck.

### Data Inspection & Management
-   **Show data**: `just show` or `just show <num_rows>` to view the data in the database.
-   **List snapshots**: `just snapshots` to see historical versions of the data.
-   **Prune history**: `just prune weeks=<num_weeks>` to delete old data.
-   **Merge files**: `just merge` to optimize the Parquet files.
